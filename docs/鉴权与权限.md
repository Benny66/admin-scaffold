# 鉴权与权限

## 认证机制

- 采用 JWT（HS256），令牌包含 `user_id`、`username`、`is_admin` 声明。
- 令牌有效期由 `jwt.expire_seconds` 配置（默认 3600 秒）。
- 密码使用 bcrypt 加密存储。

### 登录流程

```
用户提交 username/password
    → 校验用户存在且状态启用
    → 校验密码（bcrypt）
    → 生成 JWT
    → 返回 token + 用户信息 + 权限码列表
```

### 请求鉴权流程

```
请求 → JWTAuth 中间件
    → 解析 Authorization: Bearer <token>
    → 校验签名与有效期
    → 将 userID/username/isAdmin 写入 gin.Context
    → 进入路由处理器
```

## RBAC 权限模型

三级模型：**用户 → 角色 → 权限**，多对多关联。

```
User  ──many2many──  Role  ──many2many──  Permission
      (user_roles)        (role_permissions)
```

### 权限码约定

权限码格式：`<资源>:<动作>`，例如：

| 权限码 | 含义 |
|---|---|
| `users:view` | 查看用户 |
| `users:create` | 创建用户 |
| `roles:edit` | 编辑角色 |
| `dict:delete` | 删除字典 |
| `logs:view` | 查看日志 |

### 权限中间件

| 中间件 | 用途 |
|---|---|
| `middleware.AdminRequired()` | 仅超级管理员（`is_admin=true`）可访问 |
| `middleware.PermissionRequired("code")` | 需持有指定权限码（管理员自动通过） |

### 权限检查逻辑

```
1. 从 gin.Context 获取 userID
2. 若 is_admin=true → 直接放行
3. 查询用户的所有角色 → 角色关联的权限
4. 判断权限码是否命中
5. 命中放行，否则返回 403
```

## 前端权限控制

- 登录后将 `permissions`（权限码数组）与用户信息存入 Pinia 与 localStorage。
- `appStore.hasPermission(code)` 用于按钮级/菜单级控制。
- 路由守卫：未登录访问受保护页 → 跳 `/login`。

## 超级管理员

- 默认账号：`admin / admin123`。
- `is_admin=true`，拥有所有权限，跳过 RBAC 检查。
- 不可删除、不可禁用（后端有保护）。
