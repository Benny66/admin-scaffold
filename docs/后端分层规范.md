# 后端分层规范

后端 MUST 采用 `controller → service → model` 三层架构。

## 信号流

```
HTTP 请求
   │
   ▼
router ──► middleware（JWT → RBAC → 操作日志）
   │
   ▼
controller（参数解析/校验 + 调用 service + 组装响应）
   │
   ▼
service（业务逻辑 + 事务 + 数据组装，通过 GORM 访问 DB）
   │
   ▼
model（纯数据结构 + GORM tag）
   │
   ▼
database（SQLite / MySQL）
```

## 各层职责

### controllers/（控制器层）

**做什么：**
- 解析请求参数（`c.ShouldBindJSON` / `c.Query` / `c.Param`）
- 参数校验（binding tag）
- 调用 service 层方法
- 组装响应（`utils.Success` / `utils.Fail` / `utils.SuccessPage`）

**禁止：**
- ❌ 不写业务逻辑
- ❌ 不直接操作 GORM（`database.DB`）
- ❌ 不写跨模型的数据组装

### services/（业务逻辑层）

**做什么：**
- 承载所有业务逻辑
- 事务处理
- 数据组装、跨模型操作
- 通过 GORM 访问数据库

**禁止：**
- ❌ 不触碰 `gin.Context`
- ❌ 不处理 HTTP 请求/响应
- ❌ 不解析 HTTP 参数

### models/（数据模型层）

**做什么：**
- 定义数据结构
- 声明 GORM tag 与表关联
- 内嵌 `BaseModel`

**禁止：**
- ❌ 不写业务方法
- ❌ 不依赖其他层

## 依赖方向

```
controllers → services → models → database
middleware → models / utils
utils → config
```

依赖 MUST 单向向下，禁止反向依赖（如 model 依赖 service）。

## 新增模块范式

以「字典管理」为例：

1. `models/dict.go`：定义 `DictType`、`DictItem` 结构。
2. `services/dict_service.go`：实现 `GetDictTypeList`、`CreateDictType` 等业务方法。
3. `controllers/dict.go`：实现 `GetDictTypeList`（controller 同名）等，只做参数校验与响应。
4. `router/router.go`：注册路由 `dictGroup.GET("/types", controllers.GetDictTypeList)`。
5. `database/database.go`：将新模型加入 `AutoMigrate`。

## 事务处理约定

- 事务 MUST 放在 service 层，使用 `database.DB.Transaction(func(tx *gorm.DB) error { ... })`。
- controller 不感知事务。
