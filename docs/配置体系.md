# 配置体系

后端配置采用**三层覆盖机制**，优先级从低到高：

```
1. 代码内默认值（config.go 的 init 中硬编码）
2. YAML 配置文件（config.yaml，可选）
3. 环境变量（可选）
```

优先级：**环境变量 > YAML 配置 > 代码默认值**。

## 配置项清单

| 配置项 | 环境变量 | 默认值 | 说明 |
|---|---|---|---|
| `app.name` | — | 空 | 系统名称（品牌名） |
| `app.subtitle` | — | 空 | 系统副标题 |
| `app.footer` | — | 空 | 页脚文字（前端 Layout 底部显示，留空不显示） |
| `app.logo` | — | `logo.png` | 品牌 logo 文件名（放 `backend/static/`） |
| `app.favicon` | — | 空 | 浏览器标签图标文件名（放 `backend/static/`，留空回退 logo） |
| `server.port` | `BASE_BACKEND_SERVER_PORT` | `8080` | 服务端口 |
| `server.mode` | `BASE_BACKEND_GIN_MODE` | `debug` | debug/release |
| `database.type` | `BASE_BACKEND_DB_TYPE` | `sqlite` | sqlite/mysql |
| `database.sqlite.dsn` | `BASE_BACKEND_DB_DSN` | `./base_backend.db` | SQLite 路径 |
| `jwt.secret` | `BASE_BACKEND_JWT_SECRET` | 内置 | JWT 密钥 |
| `jwt.expire_seconds` | `BASE_BACKEND_JWT_EXPIRE_SECONDS` | `3600` | 过期秒数 |

## 品牌配置

品牌名称、logo、favicon、页脚四要素均可通过 `config.yaml` 的 `app` 段设置。

- **logo / favicon 文件位置**：放在 `backend/static/` 目录下，`app.logo` / `app.favicon` 填文件名（如 `logo.png`），后端自动以 `/static/<文件名>` 托管。
- **favicon 回退**：`app.favicon` 留空时回退到 `app.logo`。
- **默认 logo**：脚手架自带一张默认占位 logo（`backend/static/logo.png`），零配置启动即有品牌图；改品牌时替换该文件或改 `app.logo` 指向别的文件。
- **运行时 favicon**：前端在拉取系统信息后动态设置浏览器标签图标，无需重新构建。

### 生产部署的静态文件转发

前后端分离部署时，前端（nginx 等）需将 `/static` 路径转发到后端，否则 logo/favicon 会 404：

```nginx
location /static/ {
    proxy_pass http://127.0.0.1:8080;
}
```

开发模式已由 vite proxy 自动处理，无需额外配置。

## 使用方式

### 1. 默认配置（零配置启动）

直接 `go run main.go`，使用内置默认值，SQLite 自动建库。

### 2. YAML 配置

复制 `config.example.yaml` 为 `config.yaml`，按需修改：

```bash
cp config/config.example.yaml config.yaml
```

### 3. 环境变量覆盖

```bash
BASE_BACKEND_SERVER_PORT=9090 BASE_BACKEND_JWT_SECRET=my-secret go run main.go
```

## 配置加载逻辑

1. `init()` 先写入全部默认值。
2. `loadYAMLConfig()` 读取 `config.yaml`（优先可执行文件同目录），仅覆盖非空字段。
3. 依次检查环境变量，非空则覆盖。

## 数据库双驱动

- **sqlite**：零配置，适合开发与中小型部署，启用 WAL 模式。
- **mysql**：生产环境，需在 `database.mysql` 配置连接信息。

切换方式：修改 `database.type` 为 `mysql` 并填写 `mysql` 段。

## 配置文件位置

- 开发（`go run`）：当前工作目录的 `config.yaml`。
- 部署（编译产物）：可执行文件同目录的 `config.yaml`。

## 注意事项

- `config.yaml` 已被 `.gitignore` 忽略，不提交到版本库。
- 生产环境 MUST 修改默认 JWT 密钥。
